# Bases de diseño

Esta carpeta responde a dos preguntas: **¿cómo se da una instrucción?** y **¿cómo se sabe si quien la recibe responde por lo que hace?**

La primera se responde con el diseño de la instrucción; la segunda, con pruebas.

## Contenido

- **`Leyes de Diseño de Instrucciones.md`** — cómo se escribe algo que no se pueda saltar. Vale para una skill, un manual, un contrato o un mensaje a una máquina.
- **`Principios para agentes con autoridad/`** — cómo se juzga a quien ejecuta: qué es un mandatario, qué prueba que lo es y qué no prueba.

Son dos funciones, no dos niveles: una escribe el encargo; la otra examina a quien lo recibe.

## Orden de lectura

1. Las leyes, para saber cómo se construye una instrucción.
2. Los principios, para saber qué se le puede exigir a quien la ejecuta.
3. La **Prueba de Rendición**, para saber si la cumple.
4. La **Prueba de Utilidad Real**, para saber si ayuda a la causa.

## Regla del conjunto

Toda ley cierra con el caso que la incumple. Todo principio lleva su test. Una regla sin caso es una opinión con formato de norma.

## Dónde se prueba

- La prueba de rendición: **`Principios para agentes con autoridad/Pruebas/prueba de rendicion.md`**.
- La prueba de utilidad real: **`Principios para agentes con autoridad/Pruebas/prueba de utilidad real.md`**.
- Una implementación: **`Agentes/Proyecto S.A.R.A/Prueba de Rendición/`**.

Las pruebas no dependen de estas máquinas. La máquina es el primer caso donde se pudieron ejecutar.
