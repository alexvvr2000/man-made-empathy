# el ejemplo — un alma de tres folders, que se puede copiar y correr

**Esto no es una plantilla: es un alma que pasó.** **Se abre de arriba abajo y se ve lo que cada folder dejó.**

**Y es el ejemplo que `EMPEZAR.md` promete:** **no un texto que explica el formato, sino un alma con sus `.tra` ya llenos.** **Lo que se copia no son las palabras: es la estructura.**

**Unidad:** alma.
**Aplica a:** copiar.
**Tipo:** se corre. **Si no se puede copiar y correr, no es un ejemplo: es un dibujo.**
**Lector:** quien leyó `EMPEZAR.md` y quiere ver uno hecho.
**Dueño:** humano:autoridad.
**Estado:** vigente.

**Sesgo:** el ejemplo se lee desde el que va a copiarlo, no desde el que lo escribió.
**Límite:** **no es el mejor alma posible: es la más corta que sigue siendo un alma.** **No enseña a pensar el acto; enseña la forma.**
**Firma:** humano:autoridad · máquina:quien lo copie.

**Variables:** alma · folder · proceso · índice · `.tra`
**Peor:** el ejemplo se lee como un texto, alguien copia las palabras y no la estructura, **y acaba con tres carpetas que dicen «ejemplo» y ningún proceso que corra.**
**Quién:** quien copie el ejemplo sin cambiarle el nombre.

---

## Qué hace este alma

**Una frase, y de ahí sale todo:**

> **«Mira lo que llegó, dime si sigue llamándose igual, y avísame si le falta un dato.»**

**De esa frase salen tres pasos, y de los tres pasos salen tres folders.**

---

## Ruta — la mente

**Sesgo:** se carga el paso que sigue, no el alma entera.
**Límite:** lo que no cambia el paso siguiente no se carga.

| Se va a… | Se carga… | Sin la autoridad… |
|---|---|---|
| **copiar el ejemplo para un alma nueva** | este archivo, y los tres folders | **no se copia: se escribe uno propio** |
| **cambiarle los pasos** | `IMA.md`, y los `.tra` de los folders que cambien | **no se cambia solo el `.tra`: cambia el folder** |
| **darle otro nombre** | el folder y su `.tra`, juntos | **el ejemplo sigue diciendo «ejemplo», y miente** |
| **ver si el alma sirve** | `TALENTO.md` | **corre, y nadie sabe si sirve** |

---

## Carga — el pensamiento

| Si pasa esto | Se pierde | Y el síntoma es |
|---|---|---|
| **se copia el ejemplo sin renombrar** | el alma | hay una carpeta que dice «ejemplo», y un alma que dice otra cosa |
| **se cambia el `.tra` y no el folder** | el enlace | el nombre del folder y el de su `.tra` dejan de coincidir |
| **un folder se queda sin `.tra`** | la prueba | el alma pasó, y no hay cómo saberlo |
| **el índice no dice qué corre cada folder** | el enrutamiento | el alma entra y no sabe qué hacer |
| **se copian las palabras y no la estructura** | el ejemplo | tres carpetas con texto bonito y ningún proceso que corra |

---

## Cómo se copia

```
1. se copia la carpeta `el ejemplo` a donde viva el alma nueva.
2. se renombra la carpeta y su .tra, juntos, al nombre del acto nuevo.
3. se renombran los tres folders, y su .tra adentro, al acto de cada paso.
4. se cambia la frase de «Qué hace este alma».
5. se cambia el IMA.md para que diga los folders nuevos.
6. se llena cada .tra con lo que de verdad pasó.
```

**El paso 6 es el que casi nadie hace.** **Un `.tra` copiado con las palabras del ejemplo es una tarea que no pasó.**

---

## Prueba

**¿El ejemplo tiene sus tres folders con su `.tra`? ¿Cada `.tra` tiene su piso? ¿El índice dice qué corre cada folder? ¿Se puede copiar y correr sin leer nada más?**

**Falsificador:** un ejemplo sin `.tra`; un `.tra` con `Piso:` vacío; un folder sin fila en el índice; un ejemplo que solo se lee y no se copia; un ejemplo que se copia y sigue llamándose «ejemplo».

## Transiciones

- Se copia para un alma nueva → **se renombra todo, y se llena su `.tra` con lo que pase.**
- No se puede copiar sin entender → **el ejemplo falla: se escribe uno más corto.**
- En cualquier otro caso → **se corre, y se deja el pase.**
