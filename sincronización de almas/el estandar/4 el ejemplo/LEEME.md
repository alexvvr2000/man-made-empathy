# 4 EL EJEMPLO — un ente de punta a punta

**Aquí hay un ente ya hecho, escrito a mano, y sin una sola línea de código.**

**Sirve para ver cómo se ve terminado antes de empezar el tuyo.** **Y sirve para una cosa más: para saber que se puede hacer sin saber programar.**

## Qué trae

| | Qué es |
|---|---|
| **`lo que llega.tra`** | **una tarea: algo entra, y se dice qué lo deja mal** |
| **`el nombre.tra`** | **una tarea que nombra lo que llegó, y dice si el nombre sigue en pie** |
| **`el dato que falta.tra`** | **una tarea que se niega, y dice qué le falta — que es lo que se hace cuando no se entiende** |
| **`IMA.md`** | **el índice: qué tarea hace qué** |

## Y por qué no trae código

**Porque un ejemplo que necesita un lenguaje enseña el lenguaje, y no el ente.**

**Y porque el punto de todo esto es que no haga falta.** **Lo que hace falta es saber decir qué quieres, y saber cuándo algo falla.**

## Cómo se lee

**En orden: primero `lo que llega`, después `el nombre`, y al final `el dato que falta`.**

**Y fíjate en el tercero.** **Es el que casi nadie escribe, y es el que hace que el sistema no rompa nada: cuando no entiende, no adivina. Pregunta.**

## Lo que puedes hacer con esto

**Copiarlo, cambiarle las tareas, y tener tu primer ente hoy.** **No es un ejemplo de juguete: es la forma mínima de algo que se puede contestar.**
